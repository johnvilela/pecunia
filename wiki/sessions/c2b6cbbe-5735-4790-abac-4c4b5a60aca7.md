## What happened

Four phases in one long session: an unprompted evaluation of the whole CLI, the budgets module built end to end, four data-integrity fixes, and the transfers module built end to end — each phase closed out with its own commit(s), wiki docs committed separately per module.

### Evaluation (report only, nothing built)

User: "Evaluate 'pecunia'... Keep in mind that this is not to be built now, this is just a report about the CLI status." Read the whole repo (LOC, migrations, tests, `go vet`, PRAGMA usage, JSON/CSV support, frozen-account enforcement, `setup.go`, wiki index) before answering.

Verdict: solid foundation, terminal-shaped. Real defects flagged: currency editable without guard (silently reinterprets all history), balance hand-editable with no audit, db dir/file world-readable, frozen accounts unenforced at the store level. Latent: no WAL/busy_timeout, and read paths that write. Structural gap for what's next (chatbot/AI integration): no headless write path, no machine-readable output, orchestration living in `cmd/`. Missing features ranked above the roadmap ones: transfers, budgets, import/export.

### Budgets module ([[tasks/09-budgets-module]])

User: "Lets plan the budgets. They will be similar to the goals." Plan written to `wiki/tasks/09-budgets-module.md` first (four questions answered: one category per budget with `UNIQUE(category_id, currency)`; one amount plus a `budget_amount_log` verbatim the shape of `goal_target_log`; a card purchase counts on its charge date; a budget never refuses a transaction). Then "Ok, execute the plan to build the budget" — built via TDD exactly per the plan. Bugs the build caught that the plan didn't: `GROUP BY cycle` in the history query silently bound to the `transactions.cycle` column (the recurring-bills module's own column) instead of the `substr` alias beside it, collapsing every month into one NULL group; `pecunia ct delete` was quietly taking a category's budgets with it without saying so in the confirmation (fixed via `budgets.Store.CountForCategory`, since this migration introduced the cascade); the pace tick inside the bar was dropped, noted with a `ponytail:` comment. Verified live against the reseeded dev DB across `pecunia bg`, `--month`, `--all`, `archive`/`unarchive`, and the new summary `BUDGETS` section. Committed as `88ffca1` — `feat(budget): cap what a category may cost each month`.

Follow-up: "Update the seed with a budget over spent" — added a two-fixture over-spend scenario (`Lazer` running R$755 against a R$600 cap, split across an account and a card purchase, both dated `Days: 0` so the fixture always lands in the month being looked at). Confirmed live: `Lazer` shows over by R$155, bar clamped full, card bordered red. Noted the `ahead` state can't be pinned by a fixture — on a month's last day, pace equals the whole cap, so anything above it reads `over`, not `ahead`; a property of the pace model, not a gap.

User: "Execute the small fixes, one commit per fix." Four TDD'd fixes, each its own commit, closing four of the five real defects the evaluation had named. Full write-up: [[decisions/0013-data-integrity-fixes-and-known-gaps]].

### Transfers module ([[tasks/10-transfers]])

User: "Lets work with Transfers. This should be another category of transactions." Spec written to `wiki/tasks/10-transfers.md` first (two rows sharing `transfer_group` — an outcome on the source, an income on the destination, the group being the outcome row's own id; accounts only, never cards; two typed amounts with no rate stored, covering both cross-currency moves and fees; no category, which is the entire budget fix for free since budgets match on `category_id` and NULL matches nothing). Then built via TDD. What the build found the plan didn't: the group can't exist at the moment the legs are validated (fixed the same way `installment_group` was — write a placeholder, clear it before writing); the existing installment guard already refused a transfer leg with a serviceable message; the movement belongs in the SOURCE column, not CATEGORY (the first draft put it in CATEGORY and it read wrong under that header); `scoped` had to grow a free-function twin, `legsOfTx`, for the delete path. Verified live: both legs listed with opposite arrows, a R$5.00 fee shown on the details card, and the summary totalling neither leg while still listing both. Committed as `405085d` — `feat(transactions): move money between accounts without inflating totals`.

### Status recap and open thread

Asked "So basically we done all the suggestion you made?" — answer: about half. Fixed: currency guard, WAL/permissions, frozen enforcement, transfers. Still open: balance is a hand-editable cached aggregate with no adjustment log and no `reconcile` command (evaluation item, never revisited); `bills.Ensure` still mutates on read, survivable now under WAL but not fixed; no non-interactive write path (every create/edit is a `huh` form) and no JSON output — both block the planned chatbot/AI integration; `wiki/index.md` doesn't exist though `AGENTS.md` tells every agent to read it first. Not built: forecast module, two 20-line wins (a budget line printed after recording a transaction, `pecunia bg --uncapped`), export/import, net worth over time, a `cc delete` cascade warning matching `ct delete`'s.

Session ended immediately after the user asked "Lets do the balance reconcile fix" — no work done on it in this transcript.
