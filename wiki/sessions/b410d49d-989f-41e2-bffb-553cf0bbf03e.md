## What happened

User asked for a new `notes` module: small title, priority, status, a target time ("in 3 months", "next year", "12/12/2026"), tags, and a body — saved as one markdown file per note with SQLite holding only metadata. The one design point settled by direct follow-up before any code: "The note can have a initial LOW priority but gain priority to something like HIGH over time, the inverse can also happen" — this became the effective-score system in [[decisions/0025-notes-as-markdown-files-with-a-computed-priority]].

### Research and planning

Two Explore agents ran in parallel: one mapped the [[tasks/06-goals-module]] module end to end as the template to copy (CLI dispatch, store layer, domain model, lipgloss UI, `huh` forms, logs/audit hookup, test patterns); the other searched cross-cutting utilities — tag helpers, date parsing, `$EDITOR`/`$VISUAL` conventions (found: none existed anywhere in the repo before this session), paths/dev isolation, FTS5 availability (compiled into `modernc.org/sqlite` but unused), code-lookup and usage-counter patterns, and the MCP/Omni plugin registration shapes. A Plan agent then verified every cited fact against the repo and produced a full implementation plan (schema, package layout, front-matter grammar, date grammar, score formula, store semantics, sync semantics, commands, MCP tool, Omni command, seed fixtures, ordered commits) before any code was written.

User: "remember to create this new feature on a separated branch from main" — the branch (`feat/notes`) was in fact already checked out from local `master` right at the start of the coding phase, before the first commit; everything below was built on it.

### Build, strict TDD per [[rules/tdd]]

One commit per layer, red then green, each gated by `gofmt`/`go vet`:

1. `014_notes.sql` migration — `notes`, `note_tags`, `note_links` tables, schema tests first.
2. `internal/notes/note.go` — model, priority/status constants, `Validate`, `Slug`, `FileName`.
3. `internal/notes/frontmatter.go` — a hand-rolled YAML-subset parser (no library): `key: value`, quoted/unquoted scalars, inline and block lists, comments, a target's phrase kept as a trailing comment so "in 3 months" survives a round trip without drifting. Unknown keys are rejected by name and line, not silently ignored.
4. `internal/notes/when.go` — `ParseWhen`: ISO dates, `DD/MM/YYYY`, `YYYY-MM` (clamped to the month's last day), `today`/`tomorrow`/`next week|month|year`, `in N days|weeks|months|years`, reusing `cards.AddMonths` for the clamping month arithmetic.
5. `internal/notes/score.go` — the effective-priority algorithm (see [[decisions/0025-notes-as-markdown-files-with-a-computed-priority]] for the full formula and worked examples).
6. `internal/notes/store.go` + `files.go` — `Store` owns both the SQLite row and the markdown file; `ResolveLinks` must run before any `*sql.Tx` opens because `db.Open()` sets `SetMaxOpenConns(1)` (a cross-store lookup inside an open transaction would deadlock).
7. Lazy re-index + `Sync`/`Report` — `files_test.go`: unchanged mtime is a no-op, a changed one re-parses and updates the row without rewriting the file, a broken file sets `Problem` and is left alone, `sync` adopts orphan `.md` files and reports missing rows.
8. `internal/notes/editor.go` — `$VISUAL` then `$EDITOR` then `vi`; per-editor cursor-jump argv table (`+N` for vim family, `path:N` for helix/zed, `--goto path:N` for VS Code, `-w path:N` for Sublime); `EditFile` takes the runner as a parameter so the whole flow is testable without a terminal.
9. `go get github.com/charmbracelet/glamour@latest` for markdown rendering, landed together with the `ui.go` commit below.
10. `internal/notes/ui.go` — `Priority`, `Due`, `Table`, `Details` (glamour-rendered body), `Label`/`Pick`.
11. `cmd/notes.go` — `pecunia notes`/`n`: list (with `--all`, `--status`, `--priority`, `--min-score`, `--tag`, `--search`, `--due`, `--overdue`, `--account`/`--card`/`--goal`), `new`/`n` (interleaved-flag parsing so flags can sit before or after the title words, `--no-edit` for a scripted create), `edit`/`e`, `delete`/`d`, `sync`, bare `ID`, `--path ID`. `cmd/main.go` and `cmd/logs.go` (`note` added to `logEntities`) wired in.
12. `cmd/mcp.go` — `pecunia_notes` tool: list/get/create/update/delete/sync, patch semantics on update, `get` does **not** count as a read (an agent polling a note isn't the owner reading it).
13. `cmd/omni.go` — `/pecunia-notes [level|words]` Telegram command, `pecunia-omni.md` skill updated with the two-priority explanation (base vs. effective, never rewrite the base).
14. `scripts/seed/main.go` — four fixtures covering both score directions (a LOW note near its target with reads and a busy linked account climbs to HIGH; a HIGH note backdated 150 days with no activity sinks to LOW) plus an empty-body and a done/hidden case.
15. Follow-up fix commit: a closed (`done`/`dropped`) note now shows its base priority alone with no score and no arrow, instead of reading as if it had decayed — `Priority()`/`priorityCell()`/`scoreCell()` all check `n.Open()` first. Also: empty tag/account/card/goal lists now log as `[]` rather than `null` in the audit diff.
16. README, `cmd/skills/pecunia-overview.md` updated to mention `pecunia_notes`.
17. Version bumped `0.6.0` → `0.7.0` in `cmd/main.go`.
18. Wiki: [[decisions/0025-notes-as-markdown-files-with-a-computed-priority]] and `wiki/index.md` written and committed to the branch.

### Live verification

Against a rebuilt `dev` binary with a shell-script stand-in for `$EDITOR`: create through the editor (draft written, then adopted as `1-...md` on save), edit both unchanged (counts as a read, no rewrite) and changed (rewrites canonical, bumps edit count), every list filter (`--search`, `--tag`, `--priority` effective level, `--account`, `--due`, `--overdue`), an external hand-edit picked up lazily on the next `pecunia n`, an orphan `.md` file and a broken one both handled correctly by `pecunia n sync`, `pecunia l --entity note`, `pecunia omni notes` and `pecunia omni notes critical`, `omni-manifest` command count, and confirmation that a dev build ignores `$PECUNIA_NOTES` the same way it ignores `$PECUNIA_DB`.
