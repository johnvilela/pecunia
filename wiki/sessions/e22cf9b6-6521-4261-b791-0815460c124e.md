## What happened

Two unrelated pieces of work in one session, separated by a context compaction: fixed a date-dependent CI failure on an already-open PR, then designed and built pecunia's Omni plugin end to end.

### PR #7 CI fix: a duplicated day offset

User: "I just created a PR on pecunia, but its test suit is breaking as you can see here: https://github.com/johnvilela/pecunia/pull/7". PR #7 ("Updating wiki") was on branch `feat/setup-skills`, already checked out locally.

`gh run view --log-failed` on the failing run showed every package green except `pecunia/scripts/seed`: `TestSeedRecurring/nothing_is_dated_into_the_future` failed with "Internet is dated 2026-09-05, which has not happened yet" (today was 2026-09-04).

Root cause in `seedRecurringPayments` (`scripts/seed/main.go`): `paidOn` was computed as `paidOn.AddDate(0, 0, 2)` and explicitly clamped so nothing seeds into the future (`if paidOn.After(now) { paidOn = now }`), but the `Transaction` literal's `Date` field re-applied `paidOn.AddDate(0, 0, 2)` a second time when formatting — undoing the clamp it had just passed. Triggered by the `INTNT` (Internet) fixture (`OpenDay: 1, PaidNow: true`): its current cycle opens the 1st, +2 = the 3rd (not after "now" on the 4th, so the clamp didn't fire), then the second +2 pushed the stored date to the 5th — tomorrow. The bug was date-dependent, which is why it hadn't tripped before this particular day.

Fix: drop the second `AddDate(0, 0, 2)`, so `Date: paidOn.Format(recurring.DateLayout)`. Verified with `go test ./scripts/seed/` and the full `go test ./...`. Committed `b05fd8c` — `fix(seed): drop double day offset that dated payments into the future` (only `scripts/seed/main.go` staged), pushed to `feat/setup-skills`. `gh pr checks 7 --watch` confirmed green ("checks pass 1m6s"). Full write-up of the bug: [[tasks/07-recurring-bills-module]] (`## Update: a duplicated day offset re-broke the future-date clamp`).

After the session compacted, user: "Read the READM.md and the PLUGIN.md from https://github.com/johnvilela/omni - we will make pecunia have a Omni plugin. It will have skills to teach Omni how to use Pecunia and its philosophy, will also have telegram integration with some commands: '/pecunia-resume; /pecunia-goals; /pecunia-bills; /pecunia-cc' those commands will return the data stored formatted to telegram, wont use LLM at all. Suggest other things to make pecunia itnegrate with omni. Ask me anything to refine this." The user then picked `/pecunia-alerts`, `/pecunia-budget` and `/pecunia-add` as the suggested extras, and confirmed the existing four skills plus one new one for the skills side.
