## What happened

TDD test suite for the accounts module, a real bug caught by it, dev-mode build tooling with an isolated seeded DB, iterative list/detail UI redesign driven by screenshots, then a final commit.

### Test suite (TDD)

User: "Create a test suite for the accounts module, also anotate that we must ALWAYS use TDD to develop a new feature/module. This test suit must write in a real sqlite file but every test case must be unique and isolated, it should not depend on another test suite." Rule written up at [[rules/tdd]].

- `internal/accounts/store_test.go` restructured into subtests, each with its own SQLite file (`t.Setenv` + `t.TempDir` inside the subtest). New edge cases: `length(code)=5` CHECK bypass (Create never calls `ValidateCode`), List alphabetical order, delete frees the code, update-to-a-taken-code.
- `internal/accounts/account_test.go` — one `t.Run` per case. Added `CurrencyByCode`/`ColorByName` fallbacks, `NormalizeCode`, MinInt64 format, `RandomCode` distinctness.
- `internal/accounts/ui_test.go` — `Table`, `Details`, `pickerItem`. Substring asserts, not golden strings (lipgloss ANSI varies by profile). `Form`/`Confirm`/`Pick` need a TTY, untestable, noted in the file.
- `cmd/accounts_test.go` — dispatch: help routing, list empty/populated, `ac CODE|ID` details, freeze round trip, missing-ref errors, unopenable DB, exit codes.
- Two production changes were required by the tests: `cmd/accounts.go` — `var out io.Writer = os.Stdout`, every print routed through it so tests can capture output. `internal/accounts/store.go` — `Update` on a missing id silently returned `nil`; now returns `ErrNotFound`, same as `Delete`. That was a real bug: `pecunia ac e` on a deleted account printed "updated".
- 125 subtests green at this point, `gofmt`/`go vet` clean. Coverage: accounts 67%, cmd 58% (rest is TTY code).

### Code validation bug

User: "There was a bug when creating a new account, i decided to create my own code 'INTER' and the validation blocked it." Root cause and fix: [[gotchas/account-code-validation-vs-generation-alphabet]]. 132 subtests after the fix.

### Dev-mode build + seeded DB

User: "create a script that will build the cli with a DEV mode. It will look for database on the root of the project with seeded data. This database should be added on @.gitignore" — later renamed the binary: "the dev cli should be called 'dev' and not 'pecunia-dev'." Full writeup: [[decisions/0004-dev-build-isolated-by-ldflags]]. 141 subtests after.

### List table redesign

User, from a screenshot: "The last column is empty, i think it should not exists. The CODE and name can be one Column formatter like this: '[CODE] Name'. The currency column doesnt need to exists. The balance can display the value green if positive and red if negative." Result: `Label(a)` → `[CODE] Name` (code in the account's color, `❄` appended inline if frozen); currency column dropped (symbol already lives in the balance string); `balanceColor` green above zero, red below, default (uncolored) at zero. 152 subtests.

### Frozen accounts hidden behind --all

User: "The frozen account should not be shown unless we use the flag '--all' and it should be dimmed (like low opacity) at the end of the table." Result: `Store.List` orders `is_frozen, name` in SQL, so the picker inherits the same sinking for free; the actual filtering lives in `listAccounts(showAll)` in `cmd`, not the store, because `pecunia ac f` still needs to see frozen accounts to unfreeze them; `Label`/`balanceColor` return a dim color when frozen so the whole row greys out (code, name, balance — no green/red); `--all`/`-a` both work; two footer messages (some hidden / all hidden) guard against an empty-looking table reading as data loss.

### Detail card redesign

User: "when i enter 'pecunia ac INTER' it should show a card with the account color and the informations inside it... the fields does need to be named." Then: "There is no need to show the status and the ID. The created and update can have icons if possible." Result: bordered card colored in the account's color, no field labels — code (accent, bold, `❄` if frozen) → name (bold) → description (dim, line dropped entirely if empty) → balance (green/red) with currency code → `created`/`updated` dates with icons (`✚` created; updated icon later simplified to `#` per "Change the updatedAt icon to be just a #"). Status line and ID dropped per request. The separate color-swatch row was dropped as redundant with the border. Bubbles package deliberately not used here — this view is static output, not interactive; bubbles already drives the `ac` picker elsewhere.

Final state: 158 subtests green, `gofmt`/`go vet`/`go test` all clean.
