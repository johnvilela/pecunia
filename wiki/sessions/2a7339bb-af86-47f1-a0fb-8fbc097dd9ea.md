## What happened

One long session, split by a context compaction: built the category module end to end from [[tasks/03-category-module]], then — after compaction — built the transactions module end to end from [[tasks/04-transactions-module]].

### Category module

User: "Execute the @wiki/tasks/03-category-module.md - use caveman and design skill. Ask me anything to refine this." Two Explore agents (repo structure, wiki) ran in parallel with a background Plan agent, then four clarifying questions went to the user before any code was written:

- Seed placement → user picked **"Go seeder on `pecunia setup`"**, overriding the plan agent's own migration-based recommendation.
- `kind` column (income/expense) → deferred.
- Seed codes → fixed, human-readable (`HOME1`, `FOOD1`, `SLRY1`, ...).
- List's second column → `DESCRIPTION`, dimmed.

Implementation followed TDD cycle by cycle: `core.SuggestCode` extracted first (categories was the third caller of the same free-code loop, the ceiling a `ponytail:` comment in `internal/cards/store.go` had already named — net deletion of two copies), then schema (`004_categories.sql`), store, the 19-category `Starter` set + `Seed()`, UI, and `cmd/categories.go`. `runSetup` was changed to never return early, so a database that predates the module tops up instead of needing `--force`. Full decision write-up: [[decisions/0007-category-starter-set-seeded-from-go]].

A known hole surfaced by the Plan agent mid-implementation: `db.Open()` creates the database file on *any* command, so a user whose first command is `pecunia ct` never runs `setup` and gets an empty list rather than the starter set. Fixed at the message level, not the architecture — the empty list reads `no categories yet — run: pecunia setup, or create one with: pecunia ct n`.

Commits: `refactor(core): move the free-code search into core` → `feat: add category cli with sqlite storage and tui` → `feat(setup): seed starter categories into a new database` → `docs(wiki): record the category module`.

### Transactions module

After the context compacted, user: "@wiki/tasks/04-transactions-module.md now execute this task, ask me anything to refine it." Research this time was code-level rather than agent-delegated: read `huh`'s `Input.Suggestions()` and `bubbles/textinput` source directly and confirmed suggestions match against the *whole* input value — the reason the tags field became a filterable multi-select over tags already in use plus a separate free-text input, rather than one autocomplete input, per [[decisions/0008-transaction-double-entry-tags-and-filters]].

TDD cycles: schema (`005_transactions.sql`, plus a `transaction_tags` join table), model (`Signed()`/`CardDelta()` — a card's balance moves the *opposite* way from an account's, since `Available() = Limit - Balance`), store (one SQL transaction per write, `Update` reverses the old row before applying the new one, a card can refuse a write via `cards.Card.ValidateBalance` inside the same transaction), UI, and `cmd/transactions.go` with flag-based filters (`--date`, `--month`, `--from`/`--to`, `--tag`, `--search`, `--category`, `--account`, `--card`).

Three things beyond the original plan:
- **`cmd/main.go` gained a shared `withConn` helper**, replacing the three near-identical per-module open/defer/close copies in `accounts.go`, `cards.go` and `categories.go`.
- **`core.FKErr`** turns SQLite's `FOREIGN KEY constraint failed (787)` into a caller-supplied sentence, so deleting an account or card that still has transactions says so in `pecunia ac d`/`pecunia cc d` instead of a raw SQLite error. Backed by new `TestDeleteWhileTransactionsPointAtIt` cases in both stores' test files, using a raw `INSERT` into `transactions` to avoid an import cycle.
- **Dev seed fixtures switched from month/day literals to days-ago offsets** — simpler, and it stops the fixtures from bunching on whatever day they happen to be reseeded.

Balance math verified live against the reseeded dev DB: `NUCRD` seeded at R$1238.50, three purchases and one payment landed it at R$502.40 (confirming spending raises a card's debt, paying lowers it); `INTER` moved from R$4823.50 to R$10851.10 across its seeded transactions.

Two caveats called out explicitly at the end: the card-debt-direction model is a deliberate departure from the spec's literal wording (an outcome "decreases" both an account and a card, taken literally); and nothing reconciles a hand-edited balance (`pecunia ac e`) against its transactions — there is no `pecunia t check`.

Commits: `feat: add transactions cli with sqlite storage and tui` → `feat(accounts,cards): say what is blocking a delete` → `feat(seed): add transaction fixtures to the dev database` → `fix(transactions): tidy the list output and spread the seeded dates` → `docs(wiki): record the transactions module`.
