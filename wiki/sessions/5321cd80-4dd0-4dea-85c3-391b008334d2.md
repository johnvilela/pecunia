### Build (TDD)

Built `pecunia bill` / `b` end to end: migration `009_recurring_bills.sql`, new `internal/recurring` package (`bill.go`, `store.go`, `ui.go`), `cmd/recurring.go` wired into `cmd/main.go`. `internal/transactions` gained `Recurring` (a `Ref`) and `Cycle` (`YYYY-MM`) so a payment names both the bill and the month it was for — `ParseCycle`/`CycleOf` live in `transactions` beside the column they write; `recurring` just calls through to them. Seed fixtures added (`ENERG`, `ALUGL`, `NFLIX` on a card, `WATER` with no expected amount, `GYMXX` archived), each resolved from account/card/category codes. Full design decisions — no occurrence rows, status derived from payments, cycle stored on the payment, archive vs delete, pay opens the prefilled transaction form — in [[decisions/0011-recurring-bills-derived-from-payments]].

Two bugs caught live against the reseeded dev DB, both fixed same session: an archived bill still read "overdue" on its own card (fixed by making `StatusArchived` short-circuit `Current`, so an archived bill owes nothing anywhere it renders); a bill's own tag was dropped the first time it was paid (the transaction form only pre-selects tags it has an option for, and its options were only tags already used elsewhere — `payRecurring` now puts the bill's own tags on offer before opening the form).

`gofmt`/`go vet`/`go test ./...` clean throughout. User asked to commit ("commit this"); handled by a background subagent, outcome not confirmed by this transcript.

### Board redesigned as a lipgloss table

User, from a screenshot: "i think we should improve this using the bubbles package and the lipgloss. Maybe using a table." `Board` rewired onto `lipgloss/table` — four columns, **BILL** (code in its color + name), **AMOUNT** (right-aligned, so every figure lines up), **STATUS** (mark + word, colored by state), **WHEN** (just the date half — the status word isn't repeated in it). Same border/header style as `pecunia t` and `pecunia g --resume`. Sort order (most urgent first, tie-broken by due date then code) and the per-currency owed footer are unchanged; the footer is now indented to sit under the table's own cells rather than under the border. `state()` (used by the details card and the picker) was split so `when()` carries just the column half and `state()` stays `status — when`. `bubbles` itself was explicitly not used for the board: it's static output (`pecunia b | grep` has to keep working), which is why the repo's other lists (`pecunia t`, `pecunia g --resume`) already use `lipgloss/table` too — `bubbles/list` still drives the picker when the code is left off (`pecunia bill pay`). An interactive board (arrow to a bill, enter to pay) was offered as a follow-up if wanted, not built. User then asked to commit again — same background-subagent pattern, outcome not confirmed here either.

### Seed: a paid-this-month scenario

User: "on the seed. Add a scenario where the bill is paid too." Added a sixth fixture, `INTNT` (Internet, Vivo Fibra, R$129.90, opens 1st, due 10th), and a new `PaidNow` fixture flag that settles the current cycle as well as past ones — so the seeded board renders all five states (`upcoming`, `open`, `overdue`, `paid`, `archived`) at once instead of four. Payment dates now clamp to today when open-day+2 hasn't come round yet, so nothing seeded is ever dated into the future. Tests tightened to match: the fixture-coverage case now demands every one of the five states by name (it had been `len(states) >= 3`, which is how a missing `paid` state had slipped through undetected), plus a new case asserting no seeded payment is future-dated — both went red first, per [[rules/tdd]]. All 11 packages green, `gofmt`/`vet` clean after. User asked to commit a third time; same pattern, outcome not confirmed by this transcript.
