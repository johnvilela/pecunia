## What happened

Built [[tasks/08-summary-module]] end to end, then — later in the same session — fixed a rendering complaint that touched both the new command and the existing recurring-bills board. ### Design

Two Explore agents plus a Plan agent mapped the codebase (CLI dispatch pattern, every domain package's store/UI surface, the schema, wiki conventions, TDD rules) before any code. Seven questions went to the user; answers are recorded in [[tasks/08-summary-module]] (`summary` not `resume` — `--resume` already names the compact goals table; `--date`/`--month` as two orthogonal flags rather than a second date format; `--month` re-scopes the same sections rather than switching to a category breakdown; the full dashboard, not a snapshot; no cross-currency summing; static print, no TUI; DUE listed first).

A second Plan agent was then run specifically to pressure-test that ground truth against the real source before implementation. It confirmed the shape but forced two corrections: drop the idea of exporting `transactions.MonthRange` — `cmd/` is one package (per [[decisions/0002-flat-cmd-package-layout]]), so the existing unexported `monthRange` in `cmd/transactions.go` could be called with a zero-line diff — and fix `bills.Store`'s clock, which was unexported and only ever set to the real wall clock, meaning a summary judging bills against a given day would have judged card statements against a different, real day. It also named several traps that shaped the build: `recurring.Board` prints "no bills yet" on an empty slice (wrong sentence inside a DUE section); `Bill.Current` stands at the oldest unpaid cycle, so a bill already paid this month hides next week's occurrence from a "next 7 days" filter built on it; an overdue bill reopening next week can land in both DUE and the week-ahead section unless explicitly deduped; and a report for a past window must say nothing about what's due rather than claim a clear board it never checked.

### Build (TDD)

- `internal/summary/ui_test.go` → `ui.go` first — `Render` written before `Collect`, pinning the `Summary` struct to exactly what's printed, testable from struct literals with no database.
- `internal/bills/store_test.go` gained a case ("takes the clock it is given"); `internal/bills/store.go` gained `NewStoreAt` (three lines) so a caller that has already pinned its own "today" can hand it to the statement store instead of it reaching for the wall clock. Existing bills tests stayed green untouched.
- `internal/summary/summary_test.go` → `summary.go` (`Collect`), real SQLite file per subtest.
- `cmd/summary_test.go` → `cmd/summary.go` — flags mirror `cmd/transactions.go`'s conventions (`flag.ContinueOnError`, `fs.SetOutput(io.Discard)`, help checked before `fs.Parse`).
- `cmd/main.go` — `case "summary", "s":` plus the help line, wired in last so nothing dispatches to `runSummary` before its own tests pass.

### Bugs caught live against the reseeded dev DB

1. `bills.Store` was judging card statements against the real wall clock instead of the day the summary was asked about — fixed by `NewStoreAt`.
2. `Bill.Current` hid a bill's next occurrence once the current cycle was paid, so a bill settled this month never showed up as due again in five days — fixed by scanning this month's and next month's occurrences directly for the "next 7 days" section instead of relying on `Current`, with the bill excluded if it's already in DUE.
3. `pecunia summary --date 2026-08-11` (a day already past) claimed a clear board for bills that were never actually read — fixed so a window that's over reports nothing about what's due, rather than "nothing due".

### Follow-up: the floating "still owed" line

User, from a screenshot: "The still owned text is feeling strange there, like floating, this also happens on the bills command." — affecting both `pecunia bill`'s board and, through the shared `recurring.Board` renderer, `pecunia summary`'s DUE and NEXT 7 DAYS sections.

Root cause: `owedLine` was a separate line printed after `table.Render()`, indented two spaces, aligned to no column the table itself used.

Fix, TDD'd:
- `core.MoneyLine` added to `internal/core/ui.go` (with new cases in `internal/core/core_test.go`) — the one-figure-per-currency, sorted, `·`-joined, sign-in-front-of-symbol formatting `owedLine` already did, minus its hardcoded label and its `v > 0` filter, so it also covers a net line that can go negative.
- `recurring.Board`'s owed total moved into the table itself as its last row — the figure lands in the AMOUNT column, the label sits dim and right-aligned against it — instead of a line hanging below the border. `owedLine` deleted.
- `internal/summary/ui.go` switched its own duplicate money-formatting to `core.MoneyLine`; its own now-redundant `TestMoney` cases were removed since `core.TestMoneyLine` covers the same ground.
- The red test asserts the total sits on a line that starts with the table's own border — what "floating" meant in a form a test could check.

Wiki updated again: `tasks/07-recurring-bills-module.md` gained an `## Update: the owed total closes the table instead of hanging under it` section; `tasks/08-summary-module.md` was edited to record the same helper. Full suite clean after.
